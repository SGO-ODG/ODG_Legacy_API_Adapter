Discrepancy Categories

Category 1 — HTTP Status Mismatch 6 tests

The legacy PHP API returned a different HTTP status code than the adapter for these requests.

Impact: These are hard failures — customers receive a different status code than expected. Most involve ICD codes with trailing dots that legacy resolved via loose matching but ODG v1.2 rejects.
TestICD / URLLegacy StatusAdapter StatusRoot Cause
CGU-ODGDEMO-TEST-2 /restws/uradvisor/icd/A00./country/AU 200 404 ICD code A00. has a trailing dot. Legacy stripped it silently; adapter forwards as-is causing ODG to reject it.
CGU-ODGDEMO-TEST-36 /restws/uradvisor/icd/B86. 200 404 Same trailing dot pattern as above.
NMMutual-ODGDEMO-TEST-50 /restws/uradvisor/icd/A00. 200 404 Same trailing dot pattern as above.
Guidewire-ODGWEBSVCS-TEST-10 /restws/uradvisor/icd/I10. 200 404 Same trailing dot pattern as above. I10 is a valid ICD-10 code; I10. is malformed.
ISOCP-ODGWEBSVCS-TEST-25 20 ICD codes (long list) 500 200 Legacy returned HTTP 500 (server error) for this long multi-ICD request; adapter handled it successfully and returned 200. This is an improvement, not a regression.
RMS-ODGWEBSVCS-TEST-37 /restws/uradvisor/icd/F40.231/cpt/99152 200 404 Valid ICD-10 code F40.231 (specific phobia, animal type) that legacy resolved to guideline data but ODG v1.2 returns no results for. Possible data gap in the ODG API.
Recommendation: Add input sanitization in the adapter to strip trailing dots from ICD codes before forwarding to ODG (same fix needed as BPGuide). For F40.231 returning no results in ODG, confirm with the ODG API team whether guideline data should exist for this code.

Category 2 — Content / Format Mismatch 5 tests

Both sides returned the same HTTP status but specific field values or response format differ.

Sub-type A — rescount value differs (3 tests)

Both sides return HTTP 200 with valid data, but the rescount field value differs by 1. This indicates the adapter resolves one fewer ICD code than legacy for requests containing mixed/marginal codes in a multi-ICD list.

TestPropertyLegacy ValueAdapter Value
CityofFortWorth-ODGWEBSVCS-TEST-3 rescount 7 6
CityofFortWorth-ODGWEBSVCS-TEST-12 rescount 3 2
CityofFortWorth-ODGWEBSVCS-TEST-50 rescount 8 7
Root Cause: In each case the ICD list contains codes that the legacy PHP database resolved but ODG v1.2 does not return results for. The adapter's rescount reflects the actual number of codes with guideline data from ODG. The legacy rescount may have included codes mapped via looser fallback logic.

Sub-type B — Response format mismatch (2 tests)

These tests have a URL ending in /format/json but legacy returned XML while the adapter correctly returned JSON.

TestURLLegacy FormatAdapter FormatRoot Cause
DUR-ODGWEBSVCS-TEST-6 /restws/uradvisor/icd/format/json XML JSON The URL path /icd/format/json has no ICD value — format was parsed as the ICD code and json as a sub-segment. Legacy produced an XML 404 error; adapter correctly returns JSON 404 with the error message. The adapter behavior is correct per the /format/json contract.
PSWCA-ODGWEBSVCS-TEST-44 /restws/uradvisor/clientid/.../icd/Y926~S0101~/~W278/... XML JSON The ICD list contains an empty segment (~ between two tildes) and a bare slash, causing a path parsing anomaly. Legacy fell back to XML output; adapter correctly returned JSON as requested by /format/json. The adapter behavior is correct.
Assessment: The adapter's JSON responses for these edge-case URLs are correct. The legacy XML fallback was a quirk of the old PHP routing. No fix required in the adapter; update test expectations to accept JSON format.

Category 3 — Parse Errors 2 tests

These tests involve very long ICD code lists that exceed XML entity expansion limits during response comparison. They do not indicate a functional bug in the adapter.

TestICD CodesError
ISOCP-ODGWEBSVCS-TEST-40 13 ICD codes including M50.320, M96.1, M47.812, etc. Adapter parse failed: Entity expansion limit exceeded (1001 > 1000). Both legacy and adapter returned HTTP 200; only the comparison tool failed to parse the adapter response XML.
ISOCP-ODGWEBSVCS-TEST-44 12 ICD codes including M54.50, M25.531, etc. Both legacy and adapter parse failed with entity expansion limit. The comparison tool could not parse either response.
Assessment: The entity expansion limit is a limitation of the comparison tool's XML parser, not of the adapter. Both responses returned HTTP 200. The fix is to increase the XML parser's entity expansion limit in the compare script, or to switch to a streaming parser for very large responses.
