Discrepancy Categories

Category 1 — HTTP Status Mismatch (Legacy 404, Adapter 200) 37 tests

In all 37 failing tests, the legacy PHP API returned HTTP 404 but the adapter returned HTTP 200 with results. This is the reverse of the typical failure pattern: the adapter is returning data for queries that legacy could not handle.

Impact assessment: These are cases where the adapter returns more data than legacy. Customers who previously received a 404 (no results) will now receive actual search results. This is an improvement in coverage, not a regression. However, if any customer has downstream logic that branches on a 404, they may be affected.

Category 2 — Count Differences (COUNT_INFO — Informational Only)

The comparison script reports COUNT_INFO rows whenever the adapter returns a different number of search results than legacy for the same query. These are not failures — they are expected because:

  • ODG v1.2 has a broader and more up-to-date search index than the legacy database
  • The adapter caps results at approximately 500 per result type
  • Matching records are compared key-for-key regardless of total count

Across 287 tests, the majority have COUNT_INFO entries showing the adapter returning significantly more results than legacy (e.g. legacy returned 13 ICD10 results, adapter returned 224). This is enriched search coverage and requires no fix.
