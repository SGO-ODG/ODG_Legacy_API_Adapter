Discrepancy Categories

Category 1 — Expected Diffs: Missing stcode Field most EXPECTED_DIFF rows

The legacy PHP API returned a stcode field inside each <icdcode> element (e.g. ST347, ST880). This field is an internal legacy state-code identifier that is not available in the ODG v1.2 API response. The adapter omits it entirely. Affects all customers with EXPECTED_DIFF rows.

Assessment: No fix required. The stcode field is a legacy-internal artifact. It is not part of the documented legacy API contract delivered to customers and is not expected by adapter consumers. Mark as accepted non-breaking difference.

Category 2 — Expected Diffs: Missing Duration alert Sub-fields 295 EXPECTED_DIFF rows

The legacy API included alert sub-fields within adjustedduration.bp, adjustedduration.cp95, and adjustedduration.cp100 (e.g. <alert>yellow</alert>). These correspond to comorbidity severity indicators not yet mapped from the ODG v1.2 response. Affects 20 rows for bp.alert, 129 for cp95.alert, and 146 for cp100.alert.

Assessment: Accepted as a known gap. The alert color fields are informational in the legacy response. When the ODG v1.2 mapping is confirmed, the adapter can be updated to populate them. No customer-visible regression for the core calculator values.

Category 3 — HTTP Status Mismatch: Multiple Patterns 22 tests

22 tests across 7 customers return a different HTTP status code from legacy. There are four distinct sub-patterns.

Sub-type A — Legacy 200, Adapter 404 (DXCRM, CBCS)

DXCRM-ODGDEMO-TEST-3, DXCRM-ODGDEMO-TEST-9, and CBCS-ODGWEBSVCS-TEST-1 received HTTP 200 from the legacy PHP database but the adapter returns 404. These requests contain input combinations (NCCI codes or ICD combinations) that the legacy system resolved via older lookup tables but ODG v1.2 does not recognize.

Root Cause: Legacy database had broader fallback matching for certain NCCI/ICD inputs. ODG v1.2 returns no results for these specific inputs, causing the adapter to return a 404 no-results response. Not an adapter bug — data coverage gap in ODG v1.2.
Recommendation: Confirm with the ODG API team whether these inputs should return results. If yes, raise a data gap ticket. If no, accept the 404 and update test expectations.

Sub-type B — Legacy 400, Adapter 404 (cityofsanfrancisco ×5, GeorgiaDOAS ×3, LAWaterPower ×2)

The legacy API returned HTTP 400 (validation error) for these requests; the adapter returns 404. Both indicate failure, but the status code differs. This typically occurs when the request XML is missing required elements or contains invalid values that legacy rejected with a 400 but the adapter routes to a no-results path.

Root Cause: Legacy and adapter have slightly different error handling for malformed or incomplete calculator inputs. Legacy used a generic 400 validation response; the adapter may be treating these as no-results rather than validation failures.
Recommendation: Review the request XML for these tests to confirm whether they are validation failures (should return 400/422) or genuinely missing data (404 is acceptable). Align the adapter's error handling to match legacy behavior for these edge cases.

Sub-type C — Legacy 200, Adapter 400 (Encova ×6)

Encova-ODGWEBSVCS-TEST-8 through TEST-13: legacy returned HTTP 200 with results, but the adapter returns 400. This indicates the adapter is rejecting inputs that the legacy system accepted.

Root Cause: The adapter's input validation is stricter than legacy for certain Encova request parameters. The specific field causing the 400 needs investigation — likely a required field in the ODG v1.2 request that legacy tolerated as missing/empty.
Recommendation (High Priority): Inspect the Encova TEST-8 through TEST-13 request XML to identify which parameter triggers the 400. Adjust the adapter's validation or default handling to match the legacy permissive behavior for these inputs.

Sub-type D — Legacy 400, Adapter 200 (LAWaterPower-TEST-47, LomaLinda-TEST-19) — Improvement

In 2 tests the adapter successfully processes requests that the legacy system rejected with HTTP 400. The adapter returns a valid 200 response with results where legacy failed. This is an improvement in coverage.

Assessment: No fix required. The adapter handles these requests more robustly than legacy. Update test expectations to accept HTTP 200 for these two tests.

Category 5 — Content Mismatch: Risk Assessment Values Differ ~189 tests

The riskassessment.score, riskassessment.volatility, riskassessment.magnitude, and riskassessment.status fields return different values. Affects 189, 148, 136, and 59 tests respectively across most customers.

Root Cause: The risk scoring model in ODG v1.2 uses updated actuarial parameters compared to the legacy system. Score differences of 10–20 points on a 0–100 scale can shift the status tier (Green/Yellow/Red). This is an expected model update, not an adapter bug.
Recommendation: Confirm with Product/Clinical that ODG v1.2 risk scores represent the authoritative current model. Communicate to customers that risk scores may differ from legacy due to updated actuarial data. Update test expectations after confirmation.

Category 6 — Content Mismatch: fnolcodes Format 186 tests

The legacy API returned fnolcodes as an empty string for many records, but the adapter returns a structured object with bodypart and natureofinjury data from ODG v1.2.

Assessment: The adapter returning actual FNOL data where legacy returned nothing is an improvement. However, if customers have downstream code that checks for an empty fnolcodes element, they need to handle the new structured value. Update test expectations; no adapter fix needed.

Category 7 — Content Mismatch: Adjusted Duration Days Differ ~136 tests

The adjustedduration.cp95.days and adjustedduration.cp100.days fields differ in 136 tests each; adjustedduration.bp.days differs in 73 tests. Primarily affects customers where fulloutput=Y requests include adjusted duration data.

Root Cause: The duration day calculations use the comorbidity-adjusted duration logic in ODG v1.2, which applies updated actuarial factors. The legacy database may have used an older calculation model or a cached/rounded value. Differences are typically in the range of 5–15% of the legacy value, consistent with a model version difference.
Recommendation: Confirm with the ODG API team whether the v1.2 duration values represent the authoritative current calculation. If yes, update test expectations.

Category 8 — Content Mismatch: cfactors Trigger ICD Values Differ ~120 tests

The cfactors.depression.trigger (56 tests), cfactors.hypertension.trigger (23 tests), cfactors.diabetes.trigger (10 tests), cfactors.obesity.trigger (9 tests), cfactors.subabuse.trigger (8 tests), cfactors.smoker.trigger (5 tests), cfactors.surgery.trigger (1 test), and cfactors.opioids.trigger (1 test) values differ between legacy and adapter. Legacy used ICD-9 codes (e.g. 296.3) while the adapter returns ICD-10 equivalents (e.g. F33).

Assessment: The adapter correctly returns the ICD-10 code used as the comorbidity trigger. The legacy database had ICD-9 codes from an older dataset. This is expected for ICD-9-input claims processed against an updated ICD-10-based knowledge base. No fix required; update test expectations.

Category 9 — Content Mismatch: alertdesc and notes Format ~33 tests

The alertdesc field differs in 17 tests (CONTENT_MISMATCH on alertdesc) and 16 tests (CONTENT_MISMATCH on alertdesc.yellow). Additionally, notes.medical differs in 17 tests and notes.indemnity sub-fields in 3–4 tests each.

Root Cause: The alertdesc serialization does not yet reconstruct the legacy keyed-object format. The legacy format was <alertdesc><yellow>...</yellow></alertdesc>; the adapter currently returns an empty element or flat string. The notes field differences indicate the ODG v1.2 notes text has been updated compared to the legacy clinical notes database.
Recommendation (High Priority): Implement alertdesc keyed-object serialization in the reserve calculator response transformer. The key is the alert color level (yellow/red) and the value is the descriptive text from ODG. For notes, confirm with Product/Clinical whether the updated notes text from ODG v1.2 is authoritative.

Category 10 — Content Mismatch: Additional icdcodes Entries ~25 tests

The adapter returns additional icdcode entries in the icdcodes array (at index positions 40+) that were not present in the legacy response. These correspond to external cause codes and supplementary codes that ODG v1.2 includes but the legacy system excluded. Primarily affects tests where large ICD lists were submitted.

Assessment: No fix required. The adapter returns more complete ICD code data. These are supplementary codes consistent with a more complete knowledge base. Update test expectations.
