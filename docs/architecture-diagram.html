ODG Legacy API Adapter — Architecture & Design

Node.js / Express  ·  TypeScript  ·  Azure App Service  ·  PostgreSQL  ·  ODG API v1.2  ·  November 2026

1. Purpose

The ODG Legacy API Adapter is a temporary compatibility bridge that allows existing legacy customers to continue sending requests to the original CodeIgniter PHP API contract while the adapter translates those calls into ODG API v1.2 calls behind the scenes. Customers see zero change: the same HTTP paths, headers, XML request bodies, and response shapes they have always used continue to work without modification.

The adapter is scoped to already-subscribed legacy customers only — no new customers are provisioned through it. All five supported routes are live. All other legacy routes return a SERVICE_NOT_EXIST (403) error.

In scope: UR Advisor, Best Practice Guide, One Search, Comorbidity Calculator, Reserve Calculator (5 routes).
Out of scope: NDC Advisor, NDC Download, ProcSum, SumGuide — all return 403 and are not approximated.

3. Request Processing Pipeline

Every authenticated customer request passes through these layers in order:

# Layer Source file What it does
1 Express Entry src/app.ts Receives raw HTTP request. express.raw({ type:'*/*' }) captures the body as a Buffer regardless of Content-Type — mirrors legacy PHP's file_get_contents("php://input"). Routes to /restws or /calculator.
2 Format Selector src/middleware/formatSelector.ts Checks whether the URL path contains /format/json. Sets res.locals.legacyFormat = 'json' | 'xml' for downstream use. Default is XML.
3 Legacy Auth src/middleware/legacyAuth.ts 6-step validation chain: read X-ODG-KEY header → lookup companymaster → check disabled flag → verify service in static registry → lookup companywebservice → enforce subscription date range. Attaches req.legacy context. Returns exact legacy 403/405 error body on failure.
4 Route Handler src/routes/restws.ts
src/routes/calculator.ts		 Dispatches to the correct endpoint handler. Validates HTTP method (e.g. POST on /uradvisor returns 405). Orchestrates the transformer chain.
5 Request Transformer src/transformers/*.ts
src/parsers/*.ts		 Parses legacy input (query params, CI path segments, or XML body). Validates legacy semantics. Builds the upstream ODG v1.2 request object with correct field names, jobClass/NCCI handling, ICD family detection, deduplication, and country code.
6 ODG API Client src/upstream/odgClient.ts
src/auth/tokenCache.ts		 Retrieves cached Bearer token (or fetches one via OAuth). Calls ODG API with Authorization: Bearer and X-ApiVersion: 1.2. On 401, invalidates cache, fetches once, retries. Serializes array params in repeated-key format. 30 s timeout.
7 Response Transformer src/transformers/*.ts Maps ODG JSON response to the complete legacy model: field renaming, deep-lowercase keys (except primaryRTWpath), null→"", undefined fields stripped, array vs singleton rules, currency formatting, date formatting.
8 Serializer src/serializers/legacyResponse.ts
src/serializers/xmlBuilder.ts		 Serializes the legacy model to XML or JSON. XML preserves legacy root/wrapper element names and ordering. JSON preserves legacy field casing, singleton/array behavior, and clientid/rescount envelope.
9 Usage Logger src/middleware/usageLogger.ts Fires on res.on('finish') — after the response is sent. Inserts one row to webserviceusage. Never delays or affects the customer response. Controlled by USAGE_LOGGING_ENABLED=Y. Never logs the X-ODG-KEY or Bearer token.

5. Authentication & OAuth Token Flow

How Legacy Customers Authenticate

Customers send their existing X-ODG-KEY header — no changes are required on the customer side. The adapter validates this key against PostgreSQL before making any upstream call.

  1. Read X-ODG-KEY from request header → missing/unknown = 403
  2. Lookup companymaster → disabled = 'Y' = 403
  3. Check requested path segment against static serviceRegistry → not found = 403
  4. Lookup companywebservice for (companyCode, serviceCode) → missing = 403
  5. Enforce subscriptionStartDate → before start = 403 with start date
  6. Enforce subscriptionEndDate → after end = 403 with expiry date

How the Adapter Authenticates to ODG APIs

A single shared ODG_API_CLIENT_ID / ODG_API_CLIENT_SECRET is used for all customer calls via OAuth 2.0 Client Credentials flow. These credentials live in .env / Azure Key Vault only — never in the database.

  • Bearer token is cached in memory, shared across all customer requests
  • Cache key built from non-secret fields (token URL + client ID + audience + scopes)
  • Single-flight mechanism prevents concurrent token fetches during refresh
  • Skew: min(OAUTH_TOKEN_EXPIRY_SKEW_SECONDS, 10% of token lifetime)
  • On upstream 401: invalidate → fetch one new token → retry once — never surfaces to customer

7. Key Source Components

app.ts
src/app.ts
Creates the Express application. Mounts /restws and /calculator routers. Registers /health probe and global error handler. express.raw body parser for all routes.
legacyAuth middleware
src/middleware/legacyAuth.ts
Enforces the complete legacy auth contract. Runs before every endpoint handler. Returns exact legacy error messages on failure (403/405). Attaches req.legacy (companyCode, serviceCode, subscription).
tokenCache
src/auth/tokenCache.ts
In-memory Map keyed by non-secret cache key. Single-flight prevents concurrent token fetches. Expiry includes configurable skew. For multi-instance deployments, replace with Azure Cache for Redis.
odgClient
src/upstream/odgClient.ts
Axios instance with X-ApiVersion: 1.2, 30 s timeout, and repeated-key param serializer (icd10=A&icd10=B not icd10[]=A). Automatic 401 → invalidate → retry. Throws UpstreamError — never raw upstream bodies to callers.
Transformers
src/transformers/urAdvisor.ts · bpGuide.ts · oneSearch.ts · calculator.ts
Each transformer is self-contained: parse → validate → build upstream request → handle ODG response → build legacy model. No cross-transformer dependencies.
Serializers
src/serializers/legacyResponse.ts · xmlBuilder.ts
XML serializer preserves legacy element ordering and wraps in root/response elements. JSON serializer preserves field casing. Both apply null→"" and strip undefined fields.
usageLogger
src/middleware/usageLogger.ts
Hooks res.on('finish'). Measures wall-clock response time. Writes one row to webserviceusage asynchronously. Never blocks or throws to the request handler.
serviceRegistry
src/config/serviceRegistry.ts
Static map of 5 active services. Replaces the old webservicemaster database table. Any path segment not in the map produces SERVICE_NOT_EXIST (403) during auth.
legacyErrors
src/errors/legacyErrors.ts
Typed error catalogue with exact legacy message text and HTTP status codes. All error paths reference this catalogue — no inline error strings in route handlers or transformers.

Secrets rule: PG_PASSWORD and ODG_API_CLIENT_SECRET must be Key Vault references in Terraform app settings — never plaintext. LEGACY_PHP_REFERENCE_ROOT and any MYSQL_* variables must be omitted from Azure app settings entirely.
Multi-instance scale-out: The in-memory OAuth token cache works for a single App Service instance. For horizontal scale-out, replace src/auth/tokenCache.ts with Azure Cache for Redis so all instances share one cached token.

9. Response Serialization Rules

RuleDetail
Format selectionXML by default. JSON only when path contains exactly /format/json. No Accept header negotiation.
Key casingAll response keys deep-lowercased except primaryRTWpath which preserves mixed case.
Null valuesSerialized as empty string "" in both XML and JSON. Never emitted as the literal string "null".
Undefined fieldsStripped from output entirely — not included in XML or JSON response.
Array vs singletonMatches legacy PHP contract exactly: single-element arrays may serialize as singletons in XML depending on element type.
Upstream paramsRepeated-key format without brackets: icd10=A&icd10=B, not icd10[]=A&icd10[]=B.
CurrencyReserve Calculator cost fields formatted as currency strings matching legacy format.
ICD normalizationTrailing-dot ICD codes preserved in calculator (keepTrailingDot: true). ICD family detected by leading letter (ICD-10) vs digit-only (ICD-9).
