ODG Legacy API Adapter — Overview

Purpose

The ODG Legacy API Adapter is a Node.js/Express application that allows existing legacy customers to continue calling familiar CodeIgniter-era REST API endpoints while the adapter transparently proxies those calls to the new ODG API v1.2 using OAuth client credentials behind the scenes. It is a compatibility bridge intended to support already-subscribed customers during their migration to the new ODG APIs — no new customers are onboarded to legacy paths.

How It Works

  1. The customer sends a request with their X-ODG-KEY header (no OAuth required on their end).
  2. The adapter validates the key, checks subscription dates, and looks up the company's OAuth client credentials.
  3. A per-company OAuth token is fetched and cached to call ODG API v1.2.
  4. The upstream JSON response is transformed back into the exact legacy XML (or JSON) contract the customer expects.

Authentication

All requests must include the X-ODG-KEY header. Validation checks:

ConditionHTTP StatusError Message
Missing or unknown key403Invalid web service key.
Account is disabled403Your account is disabled.
Service not subscribed403You are not subscribed for requested web service.
Subscription not yet started403Your subscription will start from MM/DD/YYYY.
Subscription expired403Your subscription is expired on MM/DD/YYYY.

Response Format

  • Default: XML (Content-Type: application/xml)
  • JSON: Append /format/json to the path — e.g. /restws/bpguide/format/json?icd=M54.5

All legacy field names, casing, nesting, and array/singleton behavior are preserved exactly as the original PHP API produced them.

Supported API Endpoints

1. Best Practice Guide

Path: GET /restws/bpguide

JSON variant: GET /restws/bpguide/format/json

Upstream ODG API: GET /guidelines

Description

Returns ODG best practice return-to-work guidelines for one or more ICD codes. Can also accept an FNOL (body part / nature of injury) code pair which is first resolved to ICD codes via /tao/fnol/{bp}/{noi} before fetching guidelines.

Request Parameters

ParameterRequiredDescription
icdYes (or bp+noi)Tilde-separated ICD-9 or ICD-10 codes. Codes without a decimal are auto-normalized (e.g. 73556 → 735.56).
bpYes (if no icd)FNOL body-part code (zero-padded).
noiYes (if no icd)FNOL nature-of-injury code (zero-padded).
clientidNoEchoed back in response; triggers rescount field.

Response Fields (per ICD record)

FieldDescription
icdcodeICD code
nameICD description
bp[].primaryRTWpathPrimary return-to-work pathway
bp[].days1Minimum days (best practice)
bp[].daysMaximum days (claim average)
activitymod[].jobtypeJob type for activity modification
activitymod[].jobmodificationModification description
pt[].primarypathPhysical therapy pathway
pt[].visitsRecommended PT visits
pt[].weeksDuration in weeks
chiro[].primarypathChiropractic pathway
chiro[].visitsRecommended chiropractic visits
chiro[].weeksDuration in weeks
clientidEchoed client ID (when provided)
rescountNumber of records (when clientid provided)
Notes:
  • ICD-10 codes are detected by a leading letter (e.g. M54.5); ICD-9 by numeric prefix (e.g. 724.2). Mixed ICD families in one request are split and forwarded separately as icd9= and icd10= query parameters.
  • When no results are found, a 404 with { "error": "No results found for ICD code." } is returned.

2. UR Advisor

Path: GET /restws/uradvisor

JSON variant: GET /restws/uradvisor/format/json

Upstream ODG APIs: GET /tao/icds, GET /tao/procedures, GET /tao/fnol/{bp}/{noi}

Description

Returns Treatment and Outcome (TAO) utilization review data — ICD-to-procedure or procedure-to-ICD mappings with incidence rates, visit statistics, and cost benchmarks. Supports three request modes: ICD-driven lookup, procedure-to-ICD reverse lookup, and FNOL-driven lookup. Subscription outputMode=F enables full output fields.

countryNoUS (default) or AU.
flagsNoTAO filter flags (R, G, Y, B).
bpNoFNOL body-part code (used as fallback if ICD returns no results).
noiNoFNOL nature-of-injury code.
clientidNoEchoed back in response.

3. One Search

Path: POST /restws/onesearch

JSON variant: POST /restws/onesearch/format/json

Upstream ODG API: GET /search

Description

A cross-database keyword search. The client submits an XML body specifying search text and which databases to search (ICD-9, ICD-10, CPT, NDC, or Treatment Topics). Results from all selected databases are returned in a single flat list with a type discriminator field.

Request Body (XML)

<request>
  <text>knee pain</text>
  <database>
    <icd9>Y</icd9>
    <icd10>Y</icd10>
    <cpt>Y</cpt>
    <ndc>N</ndc>
    <proct>N</proct>
  </database>
  <clientid>OPTIONAL</clientid>
</request>

Database Flags to Upstream Search Types

icd10=Yicd10search
cpt=Yprocedurescpt
ndc=Yformularyndc
proct=Ytreatment

Response Fields (per result item)

FieldPresent ForDescription
typeAllICD9, ICD10, CPT, NDC, or PROCT
codeICD9, ICD10, CPT, NDCCode value
nameAllDescription or display name
brandNDC onlyTrade/proprietary name
chapterPROCT onlyPrimary chapter

clientidWhen clientid providedEchoed client ID

  • At least one <database> flag must be set to Y.

4. Comorbidity Calculator

Path: POST /calculator/comorbidity

JSON variant: POST /calculator/comorbidity/format/json

Upstream ODG API: POST /calculator with requestedoutput=RasAndRtw

Description

Calculates risk-adjusted return-to-work duration and risk assessment scores based on ICD diagnosis codes and comorbidity factors. Returns risk assessment, adjusted duration benchmarks, and adjusted summary guidelines. Does not return projected costs. adjustedduration is omitted when medicalonly=1 or medicalonly=M.

<request>
  <icdcodes>
    <code>M54.5</code>
    <code>E11.9</code>
  </icdcodes>
  <state>CA</state>
  <age>45</age>
  <datatype>WC</datatype>
  <country>US</country>
  <medicalonly>0</medicalonly>
  <fulloutput>Y</fulloutput>
  <jobclass>3</jobclass>
  <cfactors>
    <obesity>1</obesity>
    <depression>1</depression>
    <preexisting>1</preexisting>
  </cfactors>
  <procsummary>
    <cpt><code>27447</code></cpt>
  </procsummary>
  <bpcode>12</bpcode>
  <noicode>03</noicode>
  <clientid>OPTIONAL</clientid>
</request>

5. Reserve Calculator

Path: POST /calculator/reserve

JSON variant: POST /calculator/reserve/format/json

Upstream ODG API: POST /calculator with requestedoutput=RasRtwCosts

Description

Calculates risk-adjusted reserves including projected costs (indemnity, medical, expense, and total) across best practice, 95th percentile, and 100th percentile scenarios. Shares the same XML input format as the Comorbidity Calculator. Does not return adjustedsummaryguidelines. adjustedduration is included only when fulloutput=Y.

Common Behaviors Across All APIs

BehaviorDetail
ICD Code Normalization Legacy clients sometimes omit the decimal in ICD codes (e.g. 73556 → 735.56, A4545 → A45.45). The adapter normalizes these automatically before forwarding to ODG.
FNOL Code Padding Body part and nature-of-injury codes are zero-padded to ensure correct matching.
Null Serialization null values are serialized as empty strings ("") in both XML and JSON — never as the literal string "null". Fields set to undefined are stripped from output entirely.
Key Casing All legacy response keys are deep-lowercased, with the single exception of primaryRTWpath which preserves its mixed case.
Array Parameters Upstream array query parameters are sent in repeated-key format without brackets (icd10=A&icd10=B, not icd10[]=A).
EOL Endpoints POST /restws/procsum and GET /restws/sumguide are end-of-life and return an appropriate error response. They are not proxied to any ODG v1.2 endpoint.
