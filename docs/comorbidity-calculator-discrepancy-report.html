Discrepancy Categories

Category 1 — Expected Diffs: Missing stcode Field most EXPECTED_DIFF rows

The legacy PHP API returned a stcode field inside each <icdcode> element (e.g. ST347, ST880). This field is an internal legacy state-code identifier that is not available in the ODG v1.2 API response. The adapter omits it entirely.

Assessment: No fix required. The stcode field is a legacy-internal artifact. It is not part of the documented legacy API contract delivered to customers and is not expected by adapter consumers. Mark as accepted non-breaking difference.

Category 2 — Expected Diffs: Missing alert Sub-fields EXPECTED_DIFF

The legacy API included alert sub-fields within adjustedduration.bp and adjustedduration.cp95 (e.g. <alert>yellow</alert>). These correspond to comorbidity severity indicators that are not yet mapped from the ODG v1.2 response. The adapter omits these fields.

Assessment: Accepted as a known gap. The alert color fields are informational in the legacy response. When the ODG v1.2 mapping is confirmed, the adapter can be updated to populate them. No customer-visible regression for the core calculator values.

Category 3 — Content Mismatch: alertdesc Format 38 tests

The legacy API returned alertdesc as a keyed object: {"yellow": "Consider early intervention..."}. The adapter returns an empty string. This affects customers Averitt-ODGDEMO, SheakleyUniservice-ODGWEBSVCS, UnivofMichigan-ODGDEMO, and Zenith-ODGWEBSVCS.

Root Cause: The ODG v1.2 API returns comorbidity alert text differently from the legacy database. The adapter's alertdesc serialization does not yet reconstruct the keyed object format. The legacy format was <alertdesc><yellow>...</yellow></alertdesc>; the adapter currently returns an empty element.
Recommendation (High Priority): Implement alertdesc serialization in the comorbidity response transformer to produce the keyed object format matching legacy. The key is the alert color (yellow/red) and the value is the descriptive text from ODG.

Category 4 — Content Mismatch: Adjusted Duration Days Differ ~130 tests

The adjustedduration.bp.days, adjustedduration.cp95.days, and adjustedduration.cp100.days fields return different values between legacy and adapter. Affected customers: Caterpillar, CityofFortWorth, JohnsEastern, MissouriEmployersMut, PSWCA, WindhamGroup, Zenith, paradigm.

Root Cause: The duration day calculations use the comorbidity-adjusted duration logic in ODG v1.2, which applies updated actuarial factors. The legacy database may have used an older calculation model or a cached/rounded value. The differences are typically in the range of 5–15% of the legacy value, consistent with a model version difference.
Recommendation: Confirm with the ODG API team whether the v1.2 duration values represent the authoritative current calculation. If yes, update test expectations. If not, investigate whether a calculation parameter needs to be adjusted in the API request.

Category 5 — Content Mismatch: Risk Assessment Values Differ ~100 tests

The riskassessment.score, riskassessment.status, riskassessment.magnitude, and riskassessment.volatility fields return different values. Status changes such as Yellow (Cautionary) → Green (Moderate) indicate the risk threshold calculation has changed. Primarily affects Caterpillar, CityofFortWorth, JohnsEastern, PSWCA, Zenith, paradigm.

Root Cause: The risk scoring model in ODG v1.2 uses updated actuarial parameters compared to the legacy system. Score differences of 10–20 points on a 0–100 scale can shift the status tier (Green/Yellow/Red). This is an expected model update, not an adapter bug.
Recommendation: Confirm with Product/Clinical that ODG v1.2 risk scores represent the authoritative current model. Communicate to customers that risk scores may differ from legacy due to updated actuarial data.

Category 6 — Content Mismatch: fnolcodes Format 49 tests

The legacy API returned fnolcodes as an empty string for many records, but the adapter returns a structured object with bodypart and natureofinjury data from ODG v1.2. Primarily affects PSWCA-ODGWEBSVCS.

Assessment: The adapter returning actual FNOL data where legacy returned nothing is an improvement. However, if customers have downstream code that checks for an empty fnolcodes element, they need to handle the new structured value. Update test expectations; no adapter fix needed.

Category 7 — Content Mismatch: Additional icdcodes Entries ~100 tests

The adapter returns additional icdcode entries in the icdcodes array that were not present in the legacy response. These typically correspond to external cause codes (Y93.9, Y99.9, Y99.0) that ODG v1.2 includes but the legacy system excluded.

Assessment: No fix required. The adapter returns more complete ICD code data. These are supplementary external cause codes. Update test expectations.

Category 8 — Content Mismatch: cfactors Trigger ICD Values Differ ~25 tests

The cfactors.obesity.trigger, cfactors.depression.trigger, and cfactors.hypertension.trigger values differ between legacy and adapter. Legacy used ICD-9 codes (e.g. 278.0) while the adapter returns ICD-10 equivalents (e.g. E66).

Assessment: The adapter correctly returns the ICD-10 code used as the comorbidity trigger. The legacy database had ICD-9 codes from an older dataset. This is expected for ICD-9-input claims processed against an updated ICD-10-based knowledge base. No fix required; update test expectations.
